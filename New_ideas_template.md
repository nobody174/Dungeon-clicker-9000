## Feature Review

### 1. Summary

- Summarize the idea in your own words.
- Explain what player problem it solves.
- Explain why players would care.

### 2. Design Analysis

Evaluate:

- Fun factor
- Player motivation
- Long-term retention
- Progression impact
- Idle vs Active gameplay balance
- UI/UX implications
- Balance concerns
- Technical complexity
- Save-state implications
- Future expandability
- Maintenance cost

### 3. Challenge the Idea

Do not automatically agree with the proposal.

Act like a senior game designer protecting the long-term health of the game.

Identify:

- unnecessary complexity
- feature creep
- hidden dependencies
- balance problems
- progression issues
- overlapping mechanics
- better alternatives
- reasons the feature should be delayed or rejected

If a simpler solution would create a better game, recommend it.

### 4. Architecture Review

Determine whether this idea:

- fits the current architecture
- requires new systems
- depends on unfinished mechanics
- should wait until another feature exists
- affects existing save data

List every dependency explicitly.

### 5. Scope Review

If this proposal is too large, split it into logical development phases.

Recommend an implementation roadmap such as:

Phase 1
Core foundation

Phase 2
Basic gameplay

Phase 3
Player interaction

Phase 4
Future expansion

Explain why this order is the safest and easiest to maintain.

### 6. Alternative Designs

Propose:

A. Minimal version

B. Recommended version

C. Expanded version

Explain the pros and cons of each.

### 7. Recommendation

Choose ONE:

- Approve
- Approve with revisions
- Split into multiple backlog items
- Postpone
- Reject

Explain your reasoning.

Provide a high-level implementation roadmap only.

DO NOT write any code.

Stop after the review and wait for my approval.
